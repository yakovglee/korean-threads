# Ловушки

- Next.js 16 отличается от знакомых версий. Перед кодом смотреть node_modules/next/dist/docs/. `next dev` сам дописывает блок в AGENTS.md: это нормально, коммитить вместе с работой.
- Токены живут в двух местах: DESIGN.md и src/app/globals.css. Меняешь один, меняй и другой.
- PRODUCT.md в корне и specs/korean-threads/PRODUCT.md одинаковые: корневой читает /impeccable. Меняешь один, меняй и другой.
- Корейский внутри русского текста может рваться на узком экране. Проверять на ширине 320 px.
- Две сессии Claude уже правили одни файлы параллельно. Перед правками смотреть git status.
- Логика выбора темы записана дважды: инлайн-скрипт в layout.tsx и ThemeToggle.tsx. Меняешь одно, меняй и другое. useLayoutEffect в ThemeToggle не убирать: он ставит цвет theme-color, следит за системной темой и заново применяет data-theme (доки Next предупреждают, что в dev React может сбросить атрибуты <html>; в этом проекте сброс не наблюдался).
- Инлайн-скрипт темы в layout.tsx идёт без nonce. Когда появится Content-Security-Policy (TECH.md, Task 18), ему нужен nonce или hash, иначе скрипт заблокируется и тема будет мигать при загрузке.
- При правке layout.tsx на лету React в dev один раз пишет в консоль «Encountered a script tag…»: это инлайн-скрипт темы. При обычной загрузке ошибки нет.
- Проверка в браузере через Playwright оставляет в корне папку .playwright-mcp/. Она в .gitignore.
- gitleaks не установлен. Перед первым пушем поставить и прогнать (требование TECH.md).
- Vitest 4.x не ставится на npm 10.9 (ошибка arborist «edgesOut») и имеет критическую уязвимость. Vitest 5 требует @types/node ^22.
- Конфиг тестов называется vitest.config.mts: с расширением .ts Vite ругается на ESM в CommonJS.
- PGlite и postgres.js расходятся: JSON-параметр с `$n::jsonb` боевой драйвер кодирует дважды, и в базе оказывается строка. Писать `$n::text::jsonb`. Контракт Db на настоящем Postgres проверяет tests/db.real.test.ts: запускать с TEST_DATABASE_URL после любых правок слоя БД.
- DATABASE_URL в .env сейчас прямое подключение на порт 5432. Для Vercel нужен пулер Supavisor на 6543 (TECH.md), иначе соединения кончатся.
- Имена файлов из ../books на macOS приходят из readdir в NFD: перед сравнением нормализовать в NFC.
- migrate ищет supabase/migrations от process.cwd(): запускать из корня проекта.
- В dev-базе Supabase расширения vector и pg_trgm стоят в схеме public, а роли anon и authenticated имеют права на все 15 таблиц (выдача Supabase по умолчанию). Строки закрыты RLS без политик, но в Task 17 права отозвать и решить, переносить ли расширения в отдельную схему.
- Списки 등급 목록 неоднородны: в «어휘» встречаются несколько омонимов в одной ячейке через ∙ / · ‧ ・ и перевод строки внутри ячейки, в «품사» ещё и точка, в «대표형» мягкий перенос U+00AD вместо дефиса, хвостовая запятая и скобки. При обновлении файлов в ../books смотреть data/ingest-warnings.json и тест на реальных файлах: он падает, если в headword осталось что-то кроме хангыля, пробела и дефиса.
- Невидимые символы (U+00AD и подобные) в исходниках писать только escape-последовательностью `\u00ad`: литерал не виден в редакторе, и форматтер может его стереть.
- Vitest не читает .env. Если KB_SOURCE_DIR задан только там, тест на реальных файлах (tests/lists.test.ts) ищет книги в ../books, а скрипт загрузки в папке из .env. Переменную для теста задавать в окружении.
- Инструменты записи файлов у Claude превращают текст escape-последовательности (обратная косая черта, u, четыре цифры) в сам символ. Escape в исходники вносить скриптом (perl, python) и проверять байты поиском литерала.
- SQL из src/lib/memory.ts идёт мимо tests/db.real.test.ts: на настоящем Postgres его проверяет только запуск scripts/ingest-lists.ts (посев) и разовая проверка в откатываемой транзакции. Новый SQL с bigint, boolean и null проверять на dev-базе так же.
- В dev-базе Supabase extra_float_digits = 0: double precision читается с 15 значащими цифрами. Дробные значения из базы (стабильность) сравнивать с допуском, а не на точное равенство.
- google/gemini-3.8-flash (роли vision и verify) тратит выходные токены на рассуждение: ответ в одно слово стоит 75–185 выходных токенов, а при maxTokens 50 приходит пустой или обрезанный текст. Для этой модели maxTokens меньше 500 не ставить.
- Тесты клиента OpenRouter идут на фейковом fetch и расхождений с настоящим API не видят. После правок src/lib/llm.ts делать по одному настоящему запросу на роль (json, vision, embed).
- Разовые проверки вне scripts/ (они сами .env не читают), которые импортируют src/lib/llm.ts, запускать через `npx tsx --env-file=.env <файл>`: встроенное срезание типов Node падает на параметре-свойстве конструктора LlmError.
- Анализатор из ANALYZER_URL сейчас удалённый сервис по https без секрета (ANALYZER_SECRET пуст): им может пользоваться любой, кто знает адрес. Закрыть секретом до деплоя (Task 17–18).
